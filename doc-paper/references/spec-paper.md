# 学位论文体例规范 + OOXML 对照（doc-paper）

规范来源：学位论文通用排版规范（页边距 / 页码分区 / 标题层级 / 图表编号 / GB/T 7714）。
与《中文科技报告》体例（doc-format）**共用一套单位换算和引擎**，本文只写论文特有的部分。

## 一、分节与页码（md 规范「必须使用分节符」）

| 区 | 内容 | 页码 | OOXML |
|---|---|---|---|
| 封面节 | 题名 + 字段行 | **无** | sectPr 里干脆没有 `footerReference` |
| 前置节 | 摘要 / Abstract / 关键词 / 目录 | `Ⅰ Ⅱ Ⅲ` | `<w:pgNumType w:fmt="upperRoman" w:start="1"/>` + 页脚 `PAGE` 域 |
| 正文节 | 正文起，含参考文献 / 致谢 / 附录 | `1 2 3` | `<w:pgNumType w:fmt="decimal" w:start="1"/>` + 页脚 `PAGE` 域 |

**目录单独占一页**：自动插的目录，若前置区前面已排过摘要/关键词，则先插一个分页符再放目录；
源稿里显式写 `# 目录` 时，前面有内容就分页、后面还有内容（比如摘要写在目录之后）也分页。
目录后面接正文本来就有分节符，不共页。分页用**分页符**而不是分节符 —— 目录仍留在
罗马数字的前置节里，页码与摘要连算。

要点（都是实测出来的，不是推测）：

1. **PAGE 域本身不带格式开关** —— 别写 `\* ROMAN`。显示成 Ⅰ 还是 1 由**所在节的**
   `w:pgNumType/@w:fmt` 决定；`@w:start="1"` 才是「从 1 重新数」的开关，**两个节都要写**，
   否则前置节会接着封面数（封面虽不显示，页码仍在走）。
2. **封面不给页码 = 全程不碰 `sections[0].footer`。** 读了 `.footer` 就会静默创建 footer 部件；
   一旦写了 ref，封面就会有页码。
3. `Document.add_section(WD_SECTION.NEW_PAGE)` 的真实行为：把当前 body 末尾的 sectPr **克隆**
   进一个段落（＝**上一节**，保留页脚引用），sentinel 留在 body 末尾（＝新节，**页脚引用被剥掉**、
   因而是 linked 状态）。所以配置顺序是「先配节，再排内容，再 add_section」。
4. `w:pgNumType` 在 `w:sectPr` 里必须排在 **`lnNumType` 之后、`cols` 之前**（见 `thesis_xml.SECTPR_SEQ`）。
   `docx.oxml.section.CT_SectPr._tag_seq` 在运行时不存在（类体末尾被 `del` 了），顺序只能写死。
5. python-docx 1.2.0 **没有** 页码格式/起始值的 API，只能手写 XML。

## 二、标题层级（md 表格的逐字落地）

| 层级 | 字体字号 | 对齐 | outlineLvl | 其它 |
|---|---|---|---|---|
| 一级 | 黑体 **三号 16pt** 加粗 | 居中 | 0 | keepNext |
| 二级 | 黑体 四号 14pt 加粗 | 左对齐 | 1 | keepNext |
| 三级 | **楷体** 小四 12pt 加粗 | 左对齐（不缩进） | 2 | keepNext |
| 四级 | **宋体** 小四 12pt 加粗 | 左对齐（不缩进） | 3 | keepNext |
| 正文 | 宋体 + Times New Roman 小四 12pt | 两端 | — | 1.5 倍行距，首行缩进 2 字符 |

- md 写的是「黑体三号/二号」，取**三号**（`spec_paper.HEAD_PT[1]` 一处改回二号即可）。
  有些学校模板的章标题用小二 18pt，想对齐学校模板就把这里改成 18.0。
- 「左缩进」按**不缩进**实现（清掉首行缩进、左对齐）；这是中文论文里三级标题的常规排法，
  真要整段缩进就改 `spec_paper.HEAD_JC` / 给样式加 `w:left`。
- 摘要/Abstract/参考文献/致谢/附录标题都走**一级标题样式**（进目录、不占章号）。

## 三、封面

- 题名：二号(22pt) 黑体居中，自建样式 `封面题名`。
  **不能用内置 `Title`** —— 它自带 accent1 蓝下边框，会在题名下画一道蓝线。
- 字段行：四号(14pt) 宋体居中，整行照排（`作者：张三` 的标签与冒号都来自源稿，不补不改）。
- 顶部空 4 行把题名压到上半页偏上；字段行段后 12pt。
- 全部参数在 `spec_paper.COVER_*`。

## 四、公式（md：居中，编号右对齐，如 (2-1)）

### 版式：1×3 无框表格

```
│  空栏 1.75cm │  公式栏 12.0cm（居中）  │  编号栏 1.75cm（右对齐）│
```

两边留白取一样宽 → 中栏中心正好落在页心（1.75 + 12/2 = 7.75cm = 15.5/2），公式才是**真居中**。
用制表位凑不行：公式左端会随公式宽度浮动，编号位置倒是对的、公式并不居中。

表用 `Normal Table` 基座（与三线表同一招，见 doc-format 的 spec.md），固定布局，
三个单元格宽度逐格写明；空栏也要显式 `set_para_indent(clear=True)`，否则继承正文的 2 字符缩进。

### 公式本体：LaTeX → OMML，且必须用 `m:oMathPara`

`.docx` 里存 OMML（`latex_omml.py` 手写转换，不引依赖、不借 Word COM）。
**Word 不会回头解析 LaTeX** —— 存进去的是源码，显示出来就是源码，这层转换只能在生成时做完。

**关键实测结论（三条，别想当然）：**

1. **行内 `<m:oMath>` 一律按「文本式」渲染** —— 分式压成小号、∑ 的上下限挤在右侧，
   哪怕 `m:naryPr/m:limLoc="undOvr"` 也一样。
2. **`<m:oMathPara>` 才按「显示式」渲染** —— 分数满号、∑ 上下限画在上下、括号随内容放大。
3. **oMathPara 与普通 run 放在同一段就失效**（实测与行内版一模一样），所以公式必须
   **独占表格中栏那一个段落** —— 这正是 Word 自带「插入带编号公式」模板的做法。

文档级数学设置（`settings.xml` 的 `m:mathPr`：`smallFrac=0`、`naryLim=undOvr`、`dispDef`）
默认模板里本来就开着，但**管不了**行内/显示的区分 —— 那是每个公式自己的事。

### 子集与回退

支持：分式、上下标、根式、大型算符（`\sum \prod \int \oint…`，∑ 上下限在上下、∫ 在右侧）、
`\left…\right` 定界符、重音与上下划线、希腊字母与常用运算符、函数名、`\text{} \mathrm{} \mathbf{}`。
`\big/\Big` 这类只放大定界符的命令当无操作处理（忽略比整条回退强）。

**认不出来的整条回退成纯文本并给警告**，不半懂不懂地排。`--formula text` 则完全退回 LaTeX 源文本。

### 内容无损怎么查

`latex_omml.canon_text()` 给出「这条公式在 Word 里应显示成哪些字符」，
与从 `.docx` 里抠出来的 `m:t` 拼串逐字符比对。
**定界符、大型算符字符（∑ ∫）、重音符号都存在 OMML 属性里、不出现在 `m:t` 中** ——
两边都不计入，规则一致才不会假红。

另注意：`paragraph.text` **看不见数学区**（它只遍历 `w:r`），照搬会把整条公式当空的、
内容无损校验直接假绿 —— 所以 `verify_paper._docx_stream()` 单独抠 `m:t`。

## 五、参考文献（GB/T 7714-2015）

- 五号(10.5pt) 宋体/TNR，**悬挂缩进 2 字符**，1.5 倍行距，编号形式 `[1] …`。
- 源稿三种写法都认，输出统一成 `[N]`：`[1] …`、`1. …`（有序列表）、`- …`（无序列表）。
- `w:ind` 的正确写法：

```xml
<w:ind w:left="420" w:leftChars="200" w:hanging="420" w:hangingChars="200"
       w:firstLine="0" w:firstLineChars="0"/>
```

三个坑，缺一个就白写：

1. **`w:ind` 是逐属性合并的** —— 不写 `firstLine/firstLineChars`，Normal 的
   `firstLineChars=200` 会顺着 `basedOn` 链继承进来，首行照样缩进。文档级清零没用，得在这个元素上写 0。
2. **`firstLineChars` 的优先级高于 `firstLine`** —— 只写 `w:firstLine="0"` 挡不住它。
3. **悬挂 = 首行相对左缩进回退** —— 光写 `w:hanging` 不写 `w:left`，看不出效果。

```xml
<!-- 实测定稿（Word 导出 PDF 肉眼确认：首行贴左边界，折行缩进 2 字符） -->
```

另外把 `参考文献` 样式的 `basedOn` 摘掉（`base_style = None`）做双保险：
以后改 Normal 也不必再想继承链。

## 六、关键词 / 摘要

- 摘要在样式上就是正文（宋体小四 1.5 倍 首行缩进 2 字符）；英文摘要是同一段格式 ——
  Normal 的西文槽本来就是 Times New Roman 小四，**不需要额外标记**。
- 关键词行：标签（`关键词：` / `Keywords: `）黑体加粗，其余照排，不分首行缩进。
- 关键词个数 3–5（md 规定）：越界只给警告，不拦你出稿。

## 七、与 doc-format 共用的值（不要在两边各写一遍）

页边距（3.0/2.5/3.0/2.5cm）、三线表边框（1.5pt / 0.75pt）、表格内文字（五号）、
正文字号与首行缩进语义、`hp()` / `first_line_twips()` 等换算函数 —— 全部在
`doc-format/scripts/spec.py`，doc-paper 通过 `_engine.py` 引用。
改这些值会**同时**影响报告体例与论文体例，改完两个 skill 都要跑各自的 verify。
